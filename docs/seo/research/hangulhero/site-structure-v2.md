# hanguledu.com — структура сайта v2: учебная инфраструктура

Основа — СЯ v2 (`semantic-core-v2.csv`, 6 091 запрос, 351 SERP-кластер) и карта
`pages-v2.csv` (генерирует `scripts/seo/20-pages-v2.mjs`; пословно — `url-map-v2.csv`).
Заменяет `site-structure.md` (v1).

## 1. Принцип: ценность, а не текст

Текст сегодня генерирует кто угодно — он перестал быть преимуществом и сигналом качества.
Мы выигрываем тем, что AI-текстом не воспроизводится:

1. **Каждая страница — это инструмент, тренажёр или справочник с данными.** Человек что-то *делает*: слушает, печатает, считает, проверяет себя, скачивает. Текст — подпись к инструменту, а не продукт.
2. **Страницы рендерятся из данных, а не пишутся.** 12 движков × наборы данных (буквы, фразы, слова, имена) = ~140 URL. Новая страница = новая запись в JSON, а не новая статья.
3. **Собственные данные — ров.** Нативное аудио, Phrase X-Ray (как фраза *звучит* против того, как пишется), матрица обращений, раскладка с анимацией — это есть у нас (из приложения), этого нет у сайтов-конкурентов и этого не выдумает модель.
4. **Каждый инструмент ведёт в функцию приложения.** Сайт — бесплатная «демо-версия» Hangul Hero: попробовал инструмент → продолжи в приложении (аудио, повторение, офлайн, прогресс).
5. **Блога нет.** Вне фокуса (культура, факты о Корее, K-Pop, праздники как статьи, деньги, туризм) — 325 запросов сознательно исключены.

Почему это сработает именно здесь (данные R5): в 346 из 351 кластера Google показывает AI Overview — текстовый ответ он уже даёт сам. Клик получает то, что AI Overview дать не может: звук, интерактив, проверка себя, файл. Топ при этом слабый: в среднем 7 из ~8 органических мест — форумы, соцсети и мелкие сайты (медианный KD — 9).

## 4. Анатомия страницы (для любого движка)

1. **Первый экран — сам инструмент или ответ с аудио.** Без вступления: `안녕하세요 · annyeonghaseyo · ▶` / таблица / клавиатура / поле ввода.
2. **Сделай сам** — интерактив (квиз на 5 вопросов, ввод, сопоставление, печать).
3. **Данные, которых нет у других** — X-Ray-разбор, формы вежливости, матрица обращений, частотность имён.
4. **Коротко «как это работает»** — 3–6 фраз, не эссе. FAQ — только из PAA-вопросов этого кластера (R5, поле `paa` в `clusters-v2.json`).
5. **Дальше** — 4–6 связанных страниц того же движка + шаг воронки.
6. **CTA в конкретную функцию** — «Эта фраза — из пака *K-Drama Hits*. Ещё 29 с аудио и повторением — в Hangul Hero».

Schema: `WebApplication` (инструменты), `LearningResource` + `Quiz` (тренажёры, курс), `DefinedTerm` (термины и слова), `Article` — нигде, `BreadcrumbList` — везде, `MobileApplication` — на главной.

## 6. Стек: Astro, не WordPress

**Рекомендация: Astro (статическая сборка) на кодовой базе hebrewedu-site.**

| | Astro (как hebrewedu) | WordPress |
|---|---|---|
| Тип сайта, который мы строим | данные → страницы + интерактивные инструменты: ровно то, для чего Astro (islands) | CMS для *текста*; инструменты всё равно писать на JS, внутри темы и плагинов |
| 140 страниц из JSON | один шаблон на движок, `getStaticPaths` | кастомные типы записей + импорт, или ручное заполнение |
| Скорость / Core Web Vitals | статический HTML, JS только у инструментов | PHP + плагины, нужен кэш-плагин и тюнинг |
| Безопасность и поддержка | нечего взламывать — статика | обновления ядра/плагинов, админка в интернете |
| i18n (`/pt/` после R6) | уже есть в hebrewedu (`/fr/`, общие шаблоны + словари, проверка паритета) | WPML/Polylang, платно и тяжело |
| Готовое | hebrewedu: Layout, Nav/Footer, FAQ, уроки из JSON, игры, i18n, SEO-скрипты, проверки вёрстки | с нуля |
| Кто редактирует | ты и я, через git + JSON | редактор в браузере — но текстов у нас почти нет |

Другие headless CMS (Payload, Strapi, Directus) добавляют сервер и базу ради редактора, который не нужен: контент — это данные в git. Если понадобится форма для правки данных без кода — Keystatic (git-based, встраивается в Astro) позже.

**Интерактив:** Astro islands на Preact или Svelte (лёгкие); аудио — `<audio preload="none">` + спрайты; прогресс курса — `localStorage` (без аккаунтов на старте).

**Сервер:** на старте не обязателен — статику отдать через Cloudflare Pages или со своего сервера (nginx/Caddy + Cloudflare как CDN). Свой сервер пригодится во второй фазе: синхронизация прогресса сайт ↔ приложение, аккаунты, API генерации PDF-прописей (если не делать их в браузере).

**Отделение от hebrewedu:** новый репозиторий `hanguledu-site`, форк структуры (Layout, компоненты, i18n, скрипты проверок, игровой движок), без иврит-специфики. Общие движки (alphabet, letter, wordsets, games, keyboard) со временем — в общий пакет для серии HebrewEdu / HangulEdu / следующих языков: это и есть кейс «инди-EdTech» для vicsotheme.com.

## 7. Решения

1. **Сделано:** страницы на темы вне приложения (семья, числа, еда, клавиатура, имена) — *делаем*, как инструменты/наборы слов. Это 30% спроса и вес домена. Кандидаты в новые паки приложения по спросу: **Family** (115K), **Numbers** (67K), **Food** (46K), **Nicknames & terms of endearment** (62K) — тогда эти страницы тоже начнут вести в приложение.
2. **Открыто — ругательства** (`/phrases/korean-swear-words/`, 98K): большой спрос, но риск для бренда (дети в аудитории, рекламные сети). Вариант: страница без мата в заголовке, шкала грубости и «чего не говорить», без аудио самых грубых. По умолчанию — W2, решение за тобой.
3. **Язык:** глобальный английский (Индия +43% к объёму США, Филиппины +24%). Первая локализация — **pt-BR** `/pt/` после перевода листинга Play и приложения.
4. **Аудио для наборов слов:** запись носителем (лучше для E-E-A-T и уникальности) или нейро-TTS с проверкой — влияет на скорость W1 (`family`, `numbers`).
